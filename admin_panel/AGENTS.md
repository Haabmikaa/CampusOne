## Developer Instructions

### 1. Project Structure & Tech Stack
- **Framework**: Next.js 16 (App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS v4 (Headless UI for components)
- **State Management**: Redux Toolkit
- **Routing**: React Router DOM v7
- **Data Fetching**: React Query (TanStack Query)

### 2. Development Setup
- **Run Development Server**: `npm run dev` or `yarn dev`
- **Build for Production**: `npm run build`
- **Start Production Server**: `npm run start`

### 3. Code Quality & Conventions
- **Linting**: Run `npm run lint` before commits. Fix all lint errors.
- **Formatting**: Use Prettier (configured in `.prettierrc`).
- **Commit Messages**: Use Conventional Commits format (e.g., `feat: add user authentication`).
- **File Naming**: PascalCase for components (`UserProfile.tsx`), camelCase for utilities (`formatDate.ts`).
- **Component Architecture**:
  - Keep components small and focused.
  - Use TypeScript interfaces for props.
  - Prefer hooks for component logic.
  - Avoid inline styles; use Tailwind utilities or CSS Modules.

### 4. State Management
- **Redux Toolkit** is used for global state (auth, cart, etc.).
- **Reducers**: Create reducers in `src/store/slices/`.
- **Actions**: Actions are automatically generated by `createSlice`.
- **Selectors**: Use `useSelector` from `react-redux` for state access.

### 5. Routing
- **React Router DOM** is used for client-side routing.
- **Pages**: Create pages in `src/pages/` or components in `src/components/pages/`.
- **Routes**: Define routes in `src/routes/index.tsx`.
- **Protected Routes**: Use the `ProtectedRoute` component for authenticated routes.

### 6. Component Library
- **Headless UI**: Use Headless UI components from `react-headless-ui`.
- **Tailwind**: Use Tailwind CSS for all styling.
- **Custom Components**: Create reusable components in `src/components/`.

### 7. Testing
- **Unit Tests**: Create tests in `src/tests/unit/`.
- **Integration Tests**: Create tests in `src/tests/integration/`.
- **E2E Tests**: Create tests in `src/tests/e2e/`.
- **Test Runner**: Use Vitest for unit tests, Playwright for E2E tests.

### 8. Best Practices
- **Performance**: 
  - Use `React.memo`, `useMemo`, `useCallback` where appropriate.
  - Code splitting with dynamic imports.
  - Lazy loading of components.
- **Security**:
  - Never commit API keys or secrets to version control.
  - Use environment variables for sensitive data.
  - Sanitize all user inputs.
- **Accessibility**:
  - Use semantic HTML elements.
  - Ensure proper ARIA labels and roles.
  - Keyboard navigation support for all interactive elements.
